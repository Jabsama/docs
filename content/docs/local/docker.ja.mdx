ほとんどのシナリオにおいて、Docker Composeはシンプルで使いやすく、信頼性が高いため、推奨されるインストール方法です。

## 前提条件 [#prerequisites]

- [`Git`](https://git-scm.com/downloads)
- [`Docker`](https://www.docker.com/products/docker-desktop/)

ほとんどのユーザーには Docker Desktop が推奨されます。リモートサーバーへのインストールについては、[Ubuntu Docker Deployment Guide](/docs/remote/docker_linux) を参照してください。

### システム要件 [#system-requirements]

LibreChat は AI モデルそのものを実行するわけではなく、設定されたプロバイダーにリクエストを送信するため、GPU は必要ありません。

LibreChatのコンテナには、少なくとも1 GiBのRAMと1 vCPUが必要です。これはサーバーの場合と同じ[最小要件](/docs/remote#minimum-requirements)です。デフォルトのDocker Composeファイルは、LibreChatと並行して、MongoDB、Meilisearch(会話検索)、そしてPostgreSQL/pgvectorデータベース(ファイル検索)を備えたRAG APIを起動します。また、管理パネルの定義も含まれており、`.env`で`ADMIN_PANEL_SESSION_SECRET`が設定された場合にのみ起動します([管理パネル](/docs/features/admin_panel)を参照)。すべてのサービスが稼働している状態で、より快適に動作させるため、Dockerに少なくとも2 GBのメモリを割り当ててください。

Docker Desktopを使用する場合、コンテナはDocker Desktop独自の仮想マシン内で実行されるため、お使いのコンピュータもDocker Desktopの要件を満たしている必要があります。執筆時点では、要件は[macOS](https://docs.docker.com/desktop/setup/install/mac-install/)と[Linux](https://docs.docker.com/desktop/setup/install/linux/)で最低4 GBのシステムRAM、[Windows](https://docs.docker.com/desktop/setup/install/windows-install/)で8 GBのシステムRAMに加え、ハードウェア仮想化が必要です。最新の要件は、リンク先のページで確認してください。コンテナが使用できるメモリは、macOS、Linux、およびHyper-Vを使用するWindowsでは、Docker Desktopの[リソース設定](https://docs.docker.com/desktop/settings-and-maintenance/settings/)で設定します。WSL 2バックエンドを使用するWindowsでは、代わりにWSL 2仮想マシンで設定します(詳細は[DockerのWSLガイダンス](https://docs.docker.com/desktop/features/wsl/best-practices/)を参照してください)。Linux上に直接インストールされたDocker Engineはホスト上でコンテナを実行するため、別個の仮想マシンはありません。

LibreChat を同じマシン上で動作しているモデル(たとえば [Ollama](/docs/configuration/librechat_yaml/ai_endpoints/ollama))に接続する場合は、選択するモデルに合わせてハードウェアの規模を決めてください。そのモデルの実行環境は、LibreChat 本体よりもはるかに多くのメモリを必要とし、多くの場合 GPU も必要になります。

<Callout type="warn" title="Apple Silicon (Mシリーズ) Mac">

Apple Silicon (M1, M2, M3, M4) プロセッサを搭載したMacコンピュータは、LibreChatのDocker Compose設定で使用されるデフォルトのMongoDBイメージで必要とされるAVX命令をサポートしていません。MシリーズのMacを使用している場合、MongoDBは起動時にクラッシュします。

**修正:** `docker-compose.override.yml` を作成し、互換性のある古い MongoDB イメージを使用するようにします:

```yaml filename="docker-compose.override.yml"
services:
  mongodb:
    image: mongo:4.4.18
```

詳細は [Docker Override guide](/docs/configuration/docker_override) を参照してください。

</Callout>

## インストール [#installation]

<Steps>
  <Step>

### リポジトリのクローン [#clone-the-repository]

```bash
git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
```

  </Step>
  <Step>

### 環境ファイルを作成する [#create-your-environment-file]

```bash
cp .env.example .env
```

デフォルトの `.env` ファイルは、基本的なセットアップであればそのまま動作します。詳細な設定については、[.env reference](/docs/configuration/dotenv) を参照してください。

<Callout type="info" title="Windows">

On Windows, use `copy .env.example .env` if `cp` is not available.

</Callout>

  </Step>
  <Step>

### LibreChat を起動する [#start-librechat]

```bash
docker compose up -d
```

初回起動時はDockerイメージのプルが行われるため、数分かかる場合があります。2回目以降の起動は大幅に高速化されます。

  </Step>
  <Step>

### 検証とログイン [#verify-and-log-in]

ブラウザを開き、[http://localhost:3080](http://localhost:3080) にアクセスしてください。LibreChatのログインページが表示されるはずです。

<Callout type="info" title="シングルテナント環境では最初のアカウントが管理者になります">

スコープ設定のないシングルテナント環境では、最初に登録したアカウントが管理者アカウントになります。デフォルトの認証情報は存在しません。登録時に独自のユーザー名とパスワードを作成してください。テナントスコープの環境では、各テナントの最初のユーザーが自動的に昇格されることはありません。信頼できる管理フローを通じてテナント管理者をプロビジョニングしてください。

</Callout>

**Register**をクリックしてアカウントを作成し、[Your First Chat](/docs/quick_start/first_chat)に従ってモデルのAPIキーを追加し、最初のメッセージを送信してください。

  </Step>
</Steps>

## librechat.yaml のマウント [#mounting-librechatyaml]

Dockerでカスタムの `librechat.yaml` 設定ファイルを使用するには、コンテナからアクセスできるようにボリュームとしてマウントする必要があります。

サンプルオーバーライドファイルをコピーして編集します：

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

`docker-compose.override.yml` 内の librechat.yaml ボリュームマウントのコメントアウトが解除されていることを確認してください：

```yaml filename="docker-compose.override.yml"
services:
  api:
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

変更を反映させるには再起動してください:

```bash
docker compose down && docker compose up -d
```

ファイルをゼロから作成する方法を含む完全なセットアップ手順については、[librechat.yaml ガイド](/docs/configuration/librechat_yaml)を参照してください。その他のオーバーライドオプションについては、[Docker オーバーライドガイド](/docs/configuration/docker_override)を参照してください。

## LibreChat の更新 [#updating-librechat]

以下のコマンドを実行すると、Docker composeファイルの必要な変更を含むLibreChatプロジェクトの最新の変更と、最新のビルド済みイメージが取得されます。

<Callout type="info" title="権限">

環境の権限によっては、コマンドの先頭に `sudo` を付ける必要がある場合があります。

</Callout>

```bash filename="Stop the running container(s)"
docker compose down
```

```bash filename="Remove all existing docker images"
# Linux/Mac
docker images -a | grep "librechat" | awk '{print $3}' | xargs docker rmi

# Windows (PowerShell)
docker images -a --filter "reference=registry.librechat.ai/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
docker images -a --filter "reference=ghcr.io/librechat-ai/librechat*" --format "{{.ID}}" | ForEach-Object { docker rmi $_ }
```

```bash filename="Pull latest project changes"
git pull
```

```bash filename="Pull the latest LibreChat image"
docker compose pull
```

```bash filename="Start LibreChat"
docker compose up
```

## トラブルシューティング [#troubleshooting]

### ポートが既に使用されています [#port-already-in-use]

ポート3080で `bind: address already in use` のようなエラーが表示される場合、別のアプリケーションがそのポートを使用しています。

競合しているアプリケーションを停止するか、`docker-compose.override.yml` でポートを変更してください。

```yaml filename="docker-compose.override.yml"
services:
  api:
    ports:
      - "3081:3080"
```

その場合は、代わりに `http://localhost:3081` にアクセスしてください。

### コンテナが起動時にクラッシュする [#container-crashes-on-startup]

コンテナが起動直後に終了してしまう場合は、ログを確認してください：

```bash
docker compose logs api
```

一般的な原因:

- `librechat.yaml` の構文が無効です -- [YAML Validator](/toolkit/yaml_checker) で検証してください
- `.env` ファイルが見つかりません -- プロジェクトのルートディレクトリに `.env` が存在することを確認してください
- Dockerが実行されていません -- Docker Desktopが開いて実行されていることを確認してください

### 不足している環境変数 [#missing-environment-variables]

機能が期待通りに動作しない場合は、必要な環境変数が `.env` ファイルに設定されていることを確認してください。

```bash
docker compose exec api env | grep -i "your_variable"
```

利用可能なすべての変数とそのデフォルト値については、[.env reference](/docs/configuration/dotenv) を参照してください。
